### 개요 📃

현재 복잡하고 방대한 병무 행정 정보로 인해 입대 예정자들이 겪는 ‘정보 탐색의 비효율성’을 해소하고 사용자의 효율적인 입대 의사 결정에 정보 기반의 강력한 지원을 제공하기 위한 실시간 모집 경쟁률 조회와 개인 맞춤형 합격 배점 시뮬레이션을 제공하는 군 입영 지원 올인원 플랫폼입니다.

### 역할 🙋🏻‍♂️

✦ 팀 리더로서 서비스 기획, DB 설계, 개발  마일스톤 관리 및 팀원 간 기술 조율 담당

✦ 백엔드 개발자로서 공공 데이터 동기화 아키텍쳐 설계, Jsoup을 활용해 병무청의 비정형 데이터를 파싱하여 스크래핑하는 파이프라인 구축 및 사용자의 스펙과 스크래핑된 배점 기준 데이터를 매핑하여 합격 점수를 산출하는 알고리즘 구현

## 비정형 HTML 파싱 안정성 개선

### **AS-IS**

병과마다 th, rowspan 등 **HTML 테이블 구조와 셀 배치가 달라**, 고정된 위치를 기준으로 데이터를 추출할 경우 잘못된 매핑과 누락이 발생했습니다. 실제 데이터 검증 결과 **약 30~40%의 파싱 실패**를 확인했습니다.

### **TO-BE**

고정 위치 기반 파싱을 **HTML 구조에 따른 동적 매핑 방식으로 개선**하고 병과별 예외 구조를 처리했습니다. 반복 검증을 통해 **파싱 실패율을 30~40% → 0%로 개선**하여 배점 데이터 수집의 안정성을 확보했습니다.

## 외부 API 지연 문제 해결, 데이터 동기화

### AS-IS

병무청 공공데이터 API의 **불규칙한 응답 속도와 간헐적인 타임아웃**으로 조회 지연이 발생했습니다.

사용자 요청마다 외부 API를 호출하면서 **평균 2~3초의 응답 지연**이 발생하고, 외부 시스템 장애가 서비스에 직접 영향을 주는 문제가 있었습니다.

### TO-BE

데이터가 하루 단위로 갱신되는 특성을 고려하여 **Spring Scheduler 기반 데이터 동기화 구조**를 구축했습니다.

매일 데이터를 로컬 DB에 미리 동기화하고 사용자 요청은 저장된 데이터를 조회하도록 변경하여 **응답 시간을 2~3초 → 10ms 이내로 단축**하고, 외부 API 장애의 영향을 최소화했습니다.

## 비정형 HTML 스크래핑 구조 개선

### AS-IS

병과마다 **배점표의 HTML 구조와 데이터 추출 방식이 달라**, 하나의 클래스에서 여러 조건문으로 각각의 스크래핑 로직을 처리했습니다.

기능이 추가될수록 코드가 **600줄 이상으로 비대해졌고**, 새로운 병과를 추가할 때마다 기존 코드를 수정해야 하는 문제가 발생했습니다.

### TO-BE

공통 처리와 병과별 데이터 추출 로직을 분리하고 **Strategy Pattern을 적용하여 스크래핑 구조를 모듈화**했습니다.

병과별 스크래핑 로직을 독립적으로 분리하여 **새로운 병과 추가 시 기존 코드 변경을 최소화하고 새로운 모듈 추가만으로 확장할 수 있는 구조**로 개선했습니다.

## API + Web Scraping 기반 데이터 수집 파이프라인

### AS-IS

모집 현황은 **공공데이터 API(XML)**에, 상세 배점 기준은 **병무청 웹사이트(HTML)**에 존재하여 필요한 데이터가 서로 다른 형태와 출처로 분산되어 있었습니다.

이로 인해 하나의 수집 방식만으로는 **모집 정보 조회와 개인별 배점 계산에 필요한 데이터를 모두 확보하기 어려웠습니다.**

![배점기준](/non2.png)

### TO-BE

정형 데이터는 WebClient 기반 API 연동으로, 비정형 데이터는 Jsoup 기반으로 병무청의 비정형 HTML 데이터를 **스크래핑·파싱하는 데이터 수집 파이프라인 구축했습니다.**

서로 다른 형태로 수집한 데이터를 **서비스에서 활용하기 쉬운 형태로 구조화하여 DB에 통합 저장**하고, 모집 정보 조회와 개인별 배점 계산에 활용할 수 있도록 설계했습니다.
