# OAuth 연동 프로젝트에서 로컬 Postman 테스트가 막힌 이유

# 배경

관리자 출결 기능을 다 만들고 Postman으로 실제 요청을 테스트하려 했는데, 인증부터 막혔다. 직접 서명한 JWT로는 어떤 요청을 보내도 401이 떨어졌다.

```java
String token = JwtTokenProvider.createToken(userId); // 직접 서명
// → 이 토큰으로 요청하면 401
```

## 원인 파악 과정

처음엔 `JwtAuthenticationFilter`가 `principal`을 잘못 세팅하는 버그인가 의심했다. 확인해보니 인증 담당 팀원이 이미 develop에서 고쳐둔 상태였다 — 버그는 아니었다.

진짜 원인은 두 가지였다.

1. **인증 필터가 실제 세션 컨텍스트까지 검증하는 구조**였다. 카카오 OIDC 로그인 흐름을 거쳐야 서버가 세션을 만들고, 그 세션 기반으로 발급된 토큰만 유효했다. 직접 서명한 토큰은 형식은 맞아도 이 세션 검증 단계에서 걸러졌다.
2. 로컬 환경엔 **카카오 로그인용 자격 증명이 준비되어 있지 않았다.** 설정된 `KAKAO_REDIRECT_URI`가 운영 서버 주소로 되어 있어서, 로컬(`http://localhost:8080/...`)에서 카카오 로그인 흐름 자체를 탈 수가 없었다.

## 이번엔 어떻게 했나

이번 PR에서는 "Postman 테스트는 카카오 인증 인프라 제약으로 보류"라고 명시하고 제출했다. 테스트 토큰을 뽑아보려고 임시로 `TokenGeneratorTest`를 만들어봤지만, 어차피 세션 검증 단계에서 막혀서 목적을 달성하지 못했고 이후 삭제했다.

## 다음엔 이렇게 준비해두면 좋을 것 같다

OAuth 연동이 있는 프로젝트는 로컬 테스트를 위해 다음 중 하나를 미리 준비해두는 게 낫다.

- 로컬 redirect URI를 OAuth 제공자 콘솔(카카오 개발자 콘솔 등)에 미리 등록해두기
- `test`/`local` 프로파일에서만 활성화되는 인증 우회·목(mock) 로그인 엔드포인트 만들어두기
- 통합 테스트(`@SpringBootTest`)에서 `SecurityContext`를 직접 주입하는 테스트 유틸리티를 준비해서, 최소한 자동화 테스트만큼은 실제 OAuth 흐름 없이도 돌아가게 하기

## 한 줄 교훈

기능 구현이 끝나도 인증 인프라가 로컬 환경을 고려하지 않았다면 테스트가 막힐 수 있다. 이런 제약은 기능 개발 전에 팀 차원에서 먼저 확인해두는 게 좋다.
