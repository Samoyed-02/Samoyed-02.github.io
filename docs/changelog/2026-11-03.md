### 기존 URL 유지 — Hugo `aliases`

외부 링크·검색엔진 유입이 깨지지 않도록 이동한 각 글의 front matter에 기존 URL을 `aliases`로 추가했다.
Hugo는 해당 경로에 새 URL로 이동하는 리다이렉트 페이지를 생성한다.

```yaml
---
aliases: ["/posts/restrospective/cms/cms-dev-1/"]
title: "[CMS 개발기 #1] 관리자 일정 등록/수정/삭제 API"
...
```

aliases가 추가된 페이지 (21개):

| 기존 URL | 새 URL |
| --- | --- |
| `/posts/restrospective/cms/cms-1/` | `/posts/retrospective/cms/cms-1/` |
| `/posts/restrospective/cms/cms-dev-1/` ~ `cms-dev-6/` | `/posts/retrospective/cms/cms-dev-1/` ~ `cms-dev-6/` |
| `/posts/restrospective/guard-up-ideation/` | `/posts/retrospective/guard-up-ideation/` |
| `/posts/restrospective/likelion/likelion-1week/` ~ `3week/` | `/posts/retrospective/likelion/likelion-1week/` ~ `3week/` |
| `/posts/restrospective/my-first-post/` | `/posts/retrospective/my-first-post/` |
| `/posts/restrospective/pickstranger/pickstranger-1/` ~ `3/` | `/posts/retrospective/pickstranger/pickstranger-1/` ~ `3/` |
| `/posts/restrospective/pickstranger/pickstranger-azure/` | `/posts/retrospective/pickstranger/pickstranger-azure/` |
| `/posts/restrospective/wooacourse/wooacourse-1week/` | `/posts/retrospective/wooacourse/wooacourse-1week/` |
| `/posts/cs/koroutin/` | `/posts/cs/coroutine/` |
| `/projects/pickstrange/` | `/projects/pickstranger/` |

## 5. Git 인증 보안 정리

### 발견 경위

`git push`가 응답 없이 멈춰 원인을 조사하던 중, remote URL에 GitHub Personal Access Token이 평문으로 포함되어 있는 것을 발견했다.
해당 토큰은 쓰기 인증에 실패하는 상태였고, git이 VS Code askpass 비밀번호 프롬프트를 띄운 채 대기하고 있었다.

### 점검 결과

| 위치 | 상태 | 위험도 |
| --- | --- | --- |
| `Samoyed-02-blog/.git/config` | remote URL에 PAT 평문 포함 | 높음 |
| `kotlin-algorithm/.git/config` | remote URL에 PAT 평문 포함 | 높음 |
| `~/.git-credentials` | GitHub 인증 정보 평문 저장 | 중간 |
| `~/.gitconfig` | `credential.helper store` (평문 저장 방식) | 중간 |
| 블로그 저장소 파일 / git 히스토리 | 토큰 없음 (공개 저장소) | 안전 |
| macOS 키체인, `gh` CLI | 암호화 저장, 정상 로그인 | 안전 |

### 조치 내역

1. **노출된 PAT 폐기**: GitHub Settings → Developer settings에서 revoke 완료
2. **remote URL에서 토큰 제거**

   ```bash
   git remote set-url origin https://github.com/Samoyed-02/Samoyed-02.github.io.git
   ```

   `kotlin-algorithm` 저장소도 동일하게 처리

3. **인증 방식을 `gh` CLI(키체인)로 일원화**

   ```bash
   git config --global --unset-all credential.helper   # store 방식 제거
   gh auth setup-git
   ```

4. **평문 인증 파일 삭제**: `rm ~/.git-credentials`

### 검증

- 로컬 git 설정 전체에서 `ghp_` 패턴 검색 → 없음
- `git push --dry-run`, `git fetch` → 비밀번호 프롬프트 없이 정상 동작
- 이번 커밋 push도 `gh` 인증으로 정상 수행

### 재발 방지

- 토큰을 URL에 직접 넣지 않고 `gh auth login`으로만 인증
- 새 토큰이 필요하면 Fine-grained token(저장소 범위·만료일 지정) 사용
- [ ] GitHub 저장소 Secret scanning / Push protection 활성화
- [ ] `kotlin-algorithm` remote 확인: GitHub에 해당 저장소가 없음(`Repository not found`). 이름 변경 또는 삭제 여부 확인 필요

## 7. 프로필 아바타 / 파비콘 깨짐 수정

커밋 `0bc24ef`

### 증상

홈에서는 사이드바 프로필 캐릭터가 보이지만, 글·About 등 하위 페이지에서는 이미지가 깨짐. 파비콘은 모든 페이지에서 404.

### 원인

| 단계 | 내용 |
| --- | --- |
| 설정 | `hugo.toml`의 `avatar = "img/avatar.png"`, `favicon = "img/favicon.png"` |
| 테마 동작 | Stack 테마는 이 경로를 `assets/`에서 `resources.Get`으로 찾고, 찾으면 절대 경로 + width/height 생성 |
| 실제 상태 | 아바타는 `static/img/`에 있고 `assets/img/`는 비어 있음, 파비콘 파일은 아예 없음 |
| 결과 | 리소스를 못 찾아 설정값 `img/avatar.png`를 상대 경로 그대로 출력 → `/posts/cs/coroutine/img/avatar.png` 요청 → 404 |

발생 시점: `ee549b5`에서 새 아바타를 `static/img/`에 추가했고, `7644fc0`에서 기존 `assets/img/avatar.jpg`, `assets/img/favicon.png`를 삭제했다.

### 조치

- `static/img/avatar.png` → `assets/img/avatar.png` 이동 (`git mv`)
- 아바타 리사이즈: 1008×1053 (260KB) → 306×320 (36KB). 표시 크기는 약 100px
- 아바타 얼굴 부분을 잘라 64×64 `assets/img/favicon.png` 생성
- `hugo.toml` 변경 없음

### 검증

| 확인 항목 | 결과 |
| --- | --- |
| 글 페이지 아바타 `src` | `img/avatar.png` → `/img/avatar.png` (width/height 포함) |
| `/img/avatar.png` | 200 |
| `/img/favicon.png` | 404 → 200 |
| 실제 글 페이지 스크린샷 | 사이드바 프로필 정상 표시 |

### 설정

```ts
new Lenis({
    autoRaf: true,
    lerp: 0.1,            // 기술블로그 가독성을 위해 약하게
    smoothWheel: true,
    syncTouch: false,     // 모바일 터치는 네이티브 스크롤 유지
    allowNestedScroll: true,
    prevent: node => node.closest('#TableOfContents, #main-menu, .pswp') != null
});
```

### 테마 충돌 처리

| 충돌 지점 | 문제 | 해결 |
| --- | --- | --- |
| `smoothAnchors.ts` | 테마가 앵커 클릭 시 네이티브 smooth `scrollTo` 사용 → Lenis와 이중 스크롤 | 캡처 단계 click 리스너로 먼저 가로채 `lenis.scrollTo(target)`, 테마 핸들러로 전파 차단 |
| 목차 위젯 / 모바일 메뉴 | 내부 스크롤 영역 | `prevent` 옵션으로 네이티브 스크롤 유지 |

| `prefers-reduced-motion` | 접근성 | Lenis 초기화 자체를 하지 않음 |
